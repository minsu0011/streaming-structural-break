`create_next3_desktop_top20.py` checks the first 19 files against the final archive's source manifest and checks the last file against the live external verification receipt. It creates a uniquely named ordinary folder and copies, rather than moves, project files. It writes the top-20 copy receipt outside that folder so the folder remains exactly 20 files.

The ZIP also includes the router/scale/dependence/orthogonal result tables, forensic reports, initial and historical bottleneck boards, maintenance/resource/recovery logs, frozen policies, source/tests, canonical model bytes, eight figure pairs, required raw-file hashes, deployment entry mapping and detailed failed/successful receipts. It excludes raw competition observations or labels, real point OOF, feature caches, credentials, virtual environments, local wheel files, prior ZIPs and linked workspaces. Raw data must be supplied separately for a new training reproduction.

`SOURCE_MANIFEST_NEXT3.json` is generated during packaging and binds all other archive entries. Its own hash and the actual ZIP hash live in the external verification receipt to avoid a recursive self-hash. The final archive cannot contain its later external replay receipt as proof of its own completed replay; the external twentieth file supplies that post-creation evidence.

When old intermediate records say VALIDATION_ONLY, *_PENDING or PROVISIONAL, retain their historical meaning. The final selected role, actual model directory, full audit and external archive receipt are the delivery authorities. An old provisional engineering configuration remains unchanged because those exact bytes were used for reproduction; it is not a new scientific candidate.

The final completion receipt lives outside the ZIP at `artifacts/next3/handoff/SESSION_COMPLETION.json`. It is created only after the actual archive, both kinds of replay and all 20 copied files have passed. The earlier NEXT2 Desktop archive and 20-file folder remain preserved.
