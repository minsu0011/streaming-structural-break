# NEXT5 선택 불확실성의 해석

이 문서는 검증 범위를 설명한다. 현재 모델을 승격하거나 새로운 후보를 제안하는 문서가 아니다.

CV 수치도 유한한 표본에서 흔들리는 추정치다. 여러 후보 중 그 추정치가 가장 높은 후보를 선택하면, 선택 기준 자체에 과적합할 수 있다. 이 위험은 학습 모델의 과적합과 별도로 발생한다. [Cawley와 Talbot, JMLR 2010](https://www.jmlr.org/papers/v11/cawley10a.html).

튜닝에 사용한 CV의 최적값을 그대로 독립 데이터 성능으로 해석하면 편향이 생길 수 있다. 전체 선택 절차를 바깥 평가에서 다시 수행하는 nested 검증은 이 문제를 줄이는 방법이다. 해당 논문의 분류 실험 결과를 이 프로젝트의 TS-AUC에 대한 수치적 보장으로 옮기지는 않는다. [Varma와 Simon, BMC Bioinformatics 2006](https://link.springer.com/article/10.1186/1471-2105-7-91).

## 이 프로젝트에서 확인한 것

- 개별 fit의 특징 열 선택, 학습 가중치와 learner는 해당 training ID만 사용한다.
- 검증 시계열의 target은 그 fold 모델의 fit에 들어가지 않는다.
- 기준 모델과 후보의 학습 ID는 PRIMARY, ALT, H 제외 검증에서 각각 일치한다.
- 특징 생성은 해당 시계열의 H와 현재까지의 관측만 사용한다.
- X 계열은 부모의 fitted prediction을 meta feature로 사용하지 않는다. 고정된 부모 특징과 명시된 곱 좌표를 사용하므로, learned meta learner를 위한 inner-OOF는 없다.

그러나 X 부모는 ResearchPool의 관측 결과를 사용해 선택됐다. 19개 full 후보의 최종 순위 역시 같은 ResearchPool에서 결정됐다. 개별 fit의 경계가 정확하다는 사실만으로 전체 선택 절차의 성능 추정이 편향 없이 바뀌는 것은 아니다.

ALT와 H-regime 제외 학습은 같은 ResearchPool을 다시 사용한다. 이것들은 분할·배경 변화에 대한 안정성 진단이며 새 독립 표본의 확인이 아니다. 원래 H-regime 분류기의 계수는 NEXT5 이전 DEV H에서 만들어졌다는 이력도 남아 있다.

H-regime의 held-out 크기는 1,179/507/133/801/3,780개로 같지 않다. 대응 학습 크기도 5,221/5,893/6,267/5,599/2,620개다. 보고한 H-exclusion 평균은 이 다섯 regime 점수 차이의 동일 가중 평균이지 6,400개 시계열을 합친 pooled TS-AUC가 아니다. 작은 regime의 불확실성과 배경 변화, 학습 표본 수 변화가 함께 들어간 stress 검사다. 학습 크기를 맞춘 순수한 domain-shift 효과를 분리했다고 주장하지 않는다. 후보와 기준 모델은 각 regime 안에서는 같은 학습·검증 ID를 사용한다.

## Bootstrap이 답하는 질문

기존 PRIMARY fold 안에서 시계열 전체를 함께 재표본화한다. 시계열의 내부 순서와 모든 시점은 유지된다. 기준 모델과 모든 후보는 같은 2,000회 가중치를 사용한다. 예측과 학습 결과는 고정돼 있다.

`probability_delta_positive`는 그 고정된 재표본 결과에서 차이가 양수였던 비율이다. 참 성능이 개선될 베이지안 후험확률이나 다중검정 보정 p-value가 아니다. 값이 1.0이어도 독립적인 개선이 확정된다는 뜻이 아니다.

`selection_uncertainty`의 catalog envelope는 19개 고정 OOF 벡터에 대해 재표본 오차의 최대 절댓값을 요약한 것이다. 이 작업 전에 있었던 특징 설계, screen, 부모 선택, 이전 세션의 DEV 사용 및 새로운 학습에서 생길 변동은 포함하지 않는다. 따라서 전체 적응적 연구 과정의 95% 동시 신뢰보장이라고 부르지 않는다.

ALT/H 결과의 불확실성에는 기존 PRIMARY-stratified 가중치를 ID 기준으로 그대로 제한해 사용한다. 새로운 ALT별 draw를 생성하지 않으며, 새 held-out fold 안의 전체 가중치 합은 변할 수 있다. 이 설계와 조건부 해석은 `stability/POLICY_LOCK.json`에 기록했다.

## Shadow를 남겨두는 이유

Shadow는 과거에 쓰인 8,000개 DEV에서 나눴으므로 완전히 새로운 independent seal이 아니다. 이번 NEXT5의 새 후보 설계 중 결과를 보지 않도록 만든 prospective 경계다. 기존 LOCAL SEAL A/B/C/D와 같은 것으로 취급하지 않는다.

사전 계약의 공통 PRIMARY 자격을 얻은 후보가 없으면 Shadow를 열지 않는다. 특히 +0.001195650019를 +0.0012로 반올림해 자격을 만들거나, 다른 정밀도·분할·bootstrap seed를 골라 통과시키지 않는다. 이후 안정성 진단이 좋아도 이미 실패한 공통 기준을 소급 변경하지 않는다.

현재 관측값은 scale 및 late 구간에 유용한 신호가 있을 가능성을 보여준다. 동시에 같은 조건에서 B2보다 더 좋은 새 성능 세대가 확보됐다는 주장은 지지하지 못한다. 이 두 결론은 구분해서 보고한다.
